OUR TECHNOLOGY

One platform connecting device, software and response.

The project is designed as a connected safety ecosystem rather than a single device. A wearable interface can initiate an emergency event, the backend can receive and manage that event, and the safety dashboard can present available alert, device and location information in one place.

TECHNOLOGY OVERVIEW

What technologies are used?

The current project combines web technology, backend services, real-time communication, device simulation and location data. The architecture is modular so real hardware can be integrated later.

◉

Wearable Device

The proposed wearable is the user-facing safety interface. Its main purpose is to provide a simple emergency interaction such as an SOS control while remaining compact and easy to carry.

!

SOS Emergency Alerts

An emergency event is sent to the backend and displayed in the safety dashboard. The alert becomes a central event that can be monitored and managed.

⌖

Location Information

Available latitude and longitude information can be associated with a device and its emergency events, allowing the dashboard to show the location connected with an alert.

↔

Connected Backend

A Node.js and Express backend provides API endpoints for health, alerts and device information. It acts as the communication layer between the device side and dashboard.

◈

Real-Time Communication

Socket.IO is used for real-time communication so connected dashboard clients can receive system updates without relying only on manual page refreshes.

▣

Safety Dashboard

The web dashboard provides a central interface for viewing alerts, registered devices, device status, battery information and available location information.

OUR DEVICE

A wearable designed around simple emergency interaction.

The proposed Women Safety System wearable is intended to be small, convenient and easy to operate. The central idea is to provide a dedicated safety control without requiring a complicated interface during an emergency.

The current college project uses a simulated device to develop and test the complete software flow before physical hardware is finalized. This allows the backend, alert system and dashboard to be developed independently of the final wearable design.

SPECIAL FEATURES

What makes our device and system special?

The focus is on creating a simple, connected and expandable safety platform. These features are part of the current project concept and implementation.

!

Dedicated SOS Control

A dedicated emergency control gives the wearable a clear safety purpose instead of requiring the user to navigate through a complicated interface.

⚡

Fast Alert Communication

The system is designed around a direct alert flow from the device side to the backend and then to the monitoring dashboard.

⌖

Location-Aware Alerts

Available device coordinates can be associated with an alert, giving the monitoring interface useful location context.

◈

Device Health Monitoring

The system can monitor battery level, online status and the latest heartbeat received from a device.

↻

Heartbeat Monitoring

Regular heartbeat information helps the backend determine whether a connected device has recently communicated with the system.

+

Expandable Design

The software is separated into device, backend and frontend layers, making it possible to replace the simulator with physical hardware in future development.

HARDWARE TECHNOLOGY

Hardware behind the Sakhi wearable.

The current college project is a software prototype. The physical wearable is planned as the next development stage, so proposed hardware is clearly separated from what is already implemented.

HW

Current Prototype

At present, the project uses a computer/laptop and a software-based mock device to simulate the wearable, SOS events, battery information and location data.

MC

ESP32-Class Microcontroller

A future physical version can use an ESP32-class microcontroller as the main control unit for the SOS button, sensors and communication.

GPS

GPS / GNSS Module

A GPS/GNSS module can provide latitude and longitude for the wearable. The current prototype represents these coordinates through simulated device data.

SOS

Physical SOS Button

The planned wearable has a dedicated emergency button that can trigger an SOS event and send it to the connected safety system.

BAT

Rechargeable Battery

A compact rechargeable battery and power-management circuit are planned for the physical wearable, with battery level available for monitoring.

NET

Communication Module

The final device can use a suitable wireless or cellular connection. An optional GSM/LTE module is one possible future approach for independent connectivity.

NOW VS FUTURE

From software prototype to physical wearable.

Future: a physical wearable can integrate a microcontroller, SOS button, GPS/GNSS, rechargeable battery and an appropriate communication module.
